# ارزیابی انتقال‌پذیری فرهنگی ۵۴ نمونه

این محور مستقل از تعریف خشونت است. همان ۵۴ نمونهٔ انگلیسی قبلی بررسی می‌شوند: ۳۵ unsafe_violence و ۱۹ other_violence. دستهٔ اصلی، annotation خشونت و تمام متادیتای منبع حفظ می‌شوند؛ نتیجهٔ جدید در `cultural_portability` ذخیره می‌شود. دستهٔ خشونت قبلی به مدل ارزیابی فرهنگی داده نمی‌شود تا بر تصمیم جدید اثر القایی نگذارد.

## برچسب‌های جدید

| شناسه | معنی |
|---|---|
| `translation_portable` | متن شواهدی از وابستگی ضروری به زمینهٔ خاص ندارد و ترجمهٔ وفادار احتمالاً سازهٔ پژوهشی را حفظ می‌کند. تأیید جهان‌شمول بودن در تمام فرهنگ‌ها نیست. |
| `localization_required` | یک مؤلفهٔ اساسیِ وابسته به زبان/کاربردشناسی، نهاد، قانون، هنجار، زمینهٔ تاریخی/سیاسی، منابع محلی یا ارجاع گروهی وجود دارد؛ بومی‌سازی و کنترل هم‌ارزی باید با نظارت انسانی انجام شود. |
| `uncertain` | اطلاعات منبع یا دانش فرهنگی تأییدشده برای تصمیم کافی نیست؛ پرسش مشخصی برای بازبین ثبت می‌شود. این یک برچسب معتبر است و شکست API یا abstain محور خشونت نیست. |

صرف وجود نام شخص، برند یا مکان، ملاک بومی‌سازی نیست؛ وابستگی باید در معنای درخواست یا تفسیر سازهٔ پژوهشی ضروری باشد. ارزیابی به متن و شواهد خود نمونه تکیه دارد. قوانین روز یا رفتار/باور یک قوم یا ملت حدس زده نمی‌شود. برای موارد وابسته، dimension، شرح زمینهٔ منبع، شاهد، دلیل و راهنمای سطح‌بالای بازبینی انسانی الزامی‌اند. راهنما نباید متن آسیب‌رسان را برای کشور مقصد بازنویسی کند یا هدف، ابزار، مواد یا دستور عملیاتی جایگزین بسازد.

مقصد اولیه `fa-IR` و زبان توضیحات فارسی است. ارزیابی فعلی **پیش از ترجمه** و فقط از روی انگلیسی انجام می‌شود؛ `translation_tested=false` و `requires_human_review=true` اجباری‌اند. هیچ ترجمهٔ واقعی، آزمایش با مخاطبان فرهنگ مقصد، یا تأیید متخصص فرهنگی انجام نشده است. confidence فقط خودارزیابی کالیبره‌نشدهٔ مدل است. این محور برای تعیین مسیر ترجمه/بازبینی است، نه اعلام تفاوت ارزش اخلاقی خشونت میان گروه‌ها.

## اجرا و هزینه

```bash
uv run python -m pvb.portability --mode config-check
uv run python -m pvb.portability --mode run --confirm-paid-run
```

فرمان اول بدون HTTP است. تنظیمات در `configs/portability.yaml`، prompt در `configs/prompts/cultural_portability_v1.txt` و credential/model همان `GAPGPT_API_KEY` و `GAPGPT_MODEL` در `.env` هستند. خروجی در `runs/portability/pvb-portability-.../` ذخیره می‌شود. تنها متن اصلی، context و catalog شواهد به مدل ارسال می‌شوند؛ کلید و metadata منبع در prompt قرار نمی‌گیرند.

کنترل پرداخت و بودجه با همان مسیر تست‌شدهٔ GapGPT انجام می‌شود: بررسی مدل دقیق، سقف حساب حداکثر برابر `PVB_API_MAX_COST_USD`، reservation قبل از POST، درخواست‌های سریالی و تسویه بر مبنای کنتور حساب. قیمت توکنِ فرضی جایگزین تعرفهٔ سرویس نمی‌شود. مبلغ نامعلوم یا قطع‌شده کامل در reservation می‌ماند و امکان مصرف دوبارهٔ آن خودکار داده نمی‌شود. مصرف تجمعی حساب سمت ارائه‌دهنده در سقف ۲ دلار بررسی می‌شود.

## نتیجه و provenance

- `run.json`: ورودی، hash متن/prompt/implementation، تنظیمات بدون secret، شناسه‌های دقیق، مقصد و snapshot مصرف حساب.
- `model_metadata.json`: مشخصات مدل و منبع کنترل قیمت/بودجه.
- `assessments.jsonl`: همهٔ نمونه‌ها با داده‌های قبلی و تصمیم مستقل فرهنگی؛ هر تصمیم به event/run جدید وصل است.
- `portability_review.csv`: جدول شامل برچسب جدید، علت فارسی، زمینهٔ منبع، راهنمای بازبینی، ویژگی‌های لازم برای حفظ هم‌ارزی و متادیتای بنچمارک/مدل.
- `translation_portable.jsonl`، `localization_required.jsonl`، `uncertain.jsonl`: تفکیک بر اساس ارزیابی جدید.
- `manual_review_required.jsonl`: مواردی که ارائه‌دهنده نپذیرفته و ارزیابی فرهنگی مدل برای آن‌ها موجود نیست؛ با uncertainِ مدل مخلوط نمی‌شوند.
- `summary.json`: شمارش‌ها، وابستگی‌ها، جدول تقاطع دو محور و اطلاعات هزینه.
- `portability_report.html`: گزارش محلی قابل جست‌وجو و فیلتر، همراه با دلیل و اطلاعات منبع.
- `events/` و `request_events.jsonl`: درخواست، retry، مصرف، خطا و cache provenance؛ body نامعتبر upstream یا credential ذخیره نمی‌شود.

شواهد به‌صورت انتخاب index از قطعه‌های اصل متن دریافت و به نقل‌قول عیناً موجود تبدیل می‌شوند. تصمیم ناسازگار، مدل برگشتی نامنتظره، evidence ساختگی یا ادعای تست ترجمه رد می‌شود. cache این محور جدا است. annotationهای قبلی بازنویسی نمی‌شوند. نتیجهٔ فرهنگی نیز موقت و نیازمند بازبینی انسانی است.

برای ادامهٔ همان run با همان داده/روش و بدون تکرار تصمیم‌های کامل:

```bash
uv run python -m pvb.portability --mode run --confirm-paid-run --resume RUN_ID
```

رزرو هزینهٔ نامعلوم در resume حفظ می‌شود؛ resume مجوز نادیده گرفتن بودجه یا تکرار درخواست قطع‌شده نیست.

## عدم پذیرش یک نمونه توسط ارائه‌دهنده

خطای upstream داخل envelope با کد 403 به‌صورت `provider_refusal` برای همان نمونه ثبت می‌شود؛ پاسخ HTTP 403 از خود gateway همچنان خطای دسترسی است و کنترل توقف کلی آن حفظ می‌شود. برای یک نمونهٔ نپذیرفته‌شده، کشور/فرهنگ یا label فرهنگی حدس زده نمی‌شود. `portability_status=manual_review_required` و `cultural_portability=null`، همراه با مرجع run/event، این حالت را از تصمیم `uncertain` خود مدل جدا می‌کند. علت دقیق سیاست یا دسترسی ارائه‌دهنده از یک کد 403 استنتاج نمی‌شود.

گزینهٔ `prior_refusal_run` در config می‌تواند به run واقعی قبلی اشاره کند. فقط eventهای واقعاً ثبت‌شدهٔ عدم پذیرش برای همان sample_id بازیابی می‌شوند تا آن نمونه دوباره به API فرستاده نشود. تصمیم‌های کامل قبلی از cache معتبر با منشأ قبلی بازیابی می‌شوند. پایان workflow برای همهٔ نمونه‌ها می‌تواند شامل ارزیابی مدل و ارجاع مستقیم به انسان باشد؛ summary تعداد هرکدام را جدا نشان می‌دهد و هیچ مورد نپذیرفته‌شده به‌عنوان ارزیابی موفق مدل گزارش نمی‌شود.
